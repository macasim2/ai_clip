## 7. Противоречия ТЗ и принятые решения

1. **Официальный Helix vs временный GraphQL.** Раздел 3 ТЗ требует Helix, но
   особое условие запрещает делать его обязательным. Решение: `graphql` —
   провайдер по умолчанию, `helix` — полностью реализованный, но необязательный
   режим; отсутствие credentials не блокирует запуск. Переключение только через
   `.env`.
2. **Статусы.** 10 статусов из ТЗ сохраняются. Дополнительно вводятся
   `REVIEW` (недостаточно уверенности) и `ANALYSIS_ERROR` (сбой модели/JSON),
   чтобы ошибка анализа не превращалась в отклонение клипа. Это расширение,
   а не замена.
3. **Два тяжёлых LLM одновременно.** 8 GB VRAM не позволяют держать vision и
   text модели постоянно. Этапы выполняются последовательно, с
   `keep_alive`/выгрузкой; параллелизм клипов по умолчанию 1.
4. **OpenCV.** Пакет указан, но не установлен и нужен только для pHash.
   Решение: убрать зависимость, считать dHash через FFmpeg rawvideo + NumPy.
   Это не добавляет новых библиотек.
5. **Внешний API.** Локальный сценарий остаётся основным. В конфигурации
   предусматривается выбор модели/бэкенда, но внешний API не станет
   обязательным; если он не будет реализован в MVP, это будет явно указано.
6. **Python 3.14.** Проект остаётся совместимым с 3.10+, но start.bat будет
   предупреждать о непроверенных версиях; при проблемах с wheels
   рекомендуется 3.12.
7. **Скачивание.** Канонический путь — `raw_clips/<clip_id>_source.mp4`;
   старые пути с title поддерживаются как fallback, но новые файлы пишутся
   по ID.

## 10. Сравнение локальных моделей (фактические замеры)

Тест на трёх реальных клипах Twitch (5 / 6 / 9.85 с, 1920x1080 и 2560x1440),
по 3 кадра с каждого, промпты на английском и русском. Сырые результаты:
`logs/audit_bench_results.json` (локально, не в Git).

| Модель | Роль | Латентность | Качество | Вывод |
|---|---|---|---|---|
| `moondream:latest` (1B) | vision | 3.3–9.5 с/кадр, первый запрос 12.5 с | повторяющийся бред, особенно на русском; батч из 3 кадров — HTTP 400 (context 2048) | не использовать как основную |
| `llava:latest` (7B) | vision | 7–8 с/кадр (загрузка 22.7 с); батч 3 кадров 117–126 с | осмысленные английские описания, частично русские; батч очень медленный и теряет детали | основная vision-модель, **по одному кадру** |
| `llama3.2:latest` (3B) | curator | 18.9 с | JSON синтаксически валиден, но модель скопировала enum и заглушки: `"category":"Прикол|Экшен|..."`, все оценки 0, `reason:"..."` | нужен structured output + few-shot + валидация; качество под вопросом |
| `clip-judge:latest` | curator | 7.7 с | отвечает прозой, JSON не соблюдает | не использовать |
| Whisper `small` CPU int8 | ASR | 3.4 с на 9.85 с аудио | язык ru, 7 слов, текст осмысленный | оставить, кэшировать |

Дополнительно:

- При одновременной загрузке `llava` и `moondream` Ollama держала в VRAM
  ~6 GB; батч-запросы становятся аномально долгими (120 с). Нужно выгружать
  модель между этапами (`keep_alive`) и не запускать vision/text параллельно.
- Батч из 3 изображений не даёт выигрыша: llava тратит ~120 с и описывает
  последовательность общими словами. Дешевле 6–8 одиночных кадров.
- `llama3.2` без ограничения схемы не годится для строгого JSON. Проверка с
  JSON Schema в `format` (Ollama 0.40.13) и few-shot примером дала валидный
  осмысленный ответ за 7.4 с: модель корректно отклонила клип-реакцию
  (`category: "Скучное"`, `decision: "reject"`, `confidence: 0.1`). Но для
  `reject` она вернула `best_moment_start = best_moment_end = 0`, а текущий
  `validate_decision` считает это ошибкой (`be <= bs`) и пометит клип как
  FAILED. Значит, для `reject` таймкоды должны быть необязательными; это
  исправляется в этапе 4.
- Итог по моделям: `llava` — vision по умолчанию; `llama3.2` + JSON Schema +
  few-shot — рабочий локальный куратор; `moondream` и `clip-judge` — не
  использовать. Если качества `llama3.2` не хватит на реальных кандидатах,
  рекомендуется `qwen2.5:7b-instruct` (4.7 GB, влезает в 8 GB VRAM), с
  инструкцией `ollama pull`.
- Оценка времени на клип при 8 кадрах: ~60 с vision + ~4 с Whisper + ~20 с
  куратор ≈ 85 с, без учёта загрузки моделей. Для 10 клипов — около 15–20 мин.

## 11. Итог

Проект имеет хороший каркас (провайдеры, модели, строгая валидация), но
конвейер пока не является MVP: он не возобновляется после перезапуска, не
кэширует этапы, не изолирует ошибки, не использует выбранный ИИ-момент
корректно и выдаёт нечитаемые субтитры. Критические проблемы перечислены
в P0; они устраняются в этапах 2–5, проверка — в этапе 6.
