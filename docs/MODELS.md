# Выбор локальных моделей

Замеры выполнены на трёх реальных клипах Twitch (5 / 6 / 9.85 с,
1920×1080 и 2560×1440) на машине: i5-11400F, 16 GB RAM, RTX 3050 8 GB.
Сырые результаты: `logs/audit_bench_results.json` (локально, не в Git).

## Фактические результаты

| Модель | Роль | Латентность | Качество |
|---|---|---|---|
| `moondream:latest` (1B) | vision | 3–9 с/кадр | повторяющийся бред, особенно на русском; батч из 3 кадров — HTTP 400 (context 2048) |
| `llava:latest` (7B) | vision | 7–8 с/кадр; батч 3 кадров 117–126 с | осмысленные английские описания, частично русские; батч медленный и теряет детали |
| `llama3.2:latest` (3B) | curator | ~7–19 с | с JSON Schema + few-shot даёт валидный JSON и осмысленные решения; без схемы копирует enum/заглушки |
| `clip-judge:latest` | curator | ~8 с | отвечает прозой, JSON не соблюдает |
| Whisper `small` CPU int8 | ASR | ~3.4 с на 9.85 с аудио | корректный русский текст |

## Решение для MVP

- **Vision:** `llava:latest`, по одному кадру за запрос. `moondream` не
  используется: скорость не компенсирует нечитаемое качество.
- **Curator:** `llama3.2:latest` со строгой JSON Schema в `format`, few-shot
  примером и повторной попыткой. При низкой `confidence` решение
  понижается до `review`, а не выдаётся за кандидат.
- **ASR:** `small` на CPU/int8; модель кэшируется, транскрипт сохраняется в
  `transcript.json` и не пересчитывается.
- **Двухступенчатость:** vision-модель описывает кадры, текстовая модель
  собирает последовательность и принимает решение. Это уже два разных
  прохода; отдельная «сильная» модель не обязательна на 8 GB VRAM.

## VRAM и порядок работы

- `llava` занимает ~4.7 GB VRAM, `llama3.2` ~2 GB, `moondream` ~1.25 GB.
- При одновременной загрузке vision и text моделей Ollama держала ~6 GB;
  батч-запросы становились аномально долгими. Модели нужно выгружать
  (`OLLAMA_KEEP_ALIVE`) и не запускать vision/text параллельно.
- `MAX_PARALLEL=1` по умолчанию. Увеличение параллелизма не помогает на одной
  GPU и может привести к нехватке VRAM.

## Если качества `llama3.2` не хватит

Рекомендуется `qwen2.5:7b-instruct` (~4.7 GB, влезает в 8 GB VRAM):

```bat
ollama pull qwen2.5:7b-instruct
```

и в `.env`:

```env
OLLAMA_TEXT_MODEL=qwen2.5:7b-instruct
```

Модель куратора меняется только конфигурацией; pipeline, база и downloader
не зависят от конкретного имени.

## Проверка на реальном клипе

Для клипа-реакции `727687811` («что», 9.85 с) новая схема дала валидный JSON:

```json
{
  "category": "Экшен",
  "event_description": "G2 returns to full strength",
  "unexpectedness": 0.2,
  "emotionality": 0.2,
  "payoff_strength": 0.4,
  "event_clarity": 0.6,
  "visual_interest": 0.4,
  "hook_strength": 0.3,
  "context_independence": 0.5,
  "overall_score": 0,
  "confidence": 0.1,
  "decision": "reject",
  "best_moment_start": 0.0,
  "best_moment_end": 0.0,
  "reason": "Lack of clear event with a payoff or reaction"
}
```

Взвешенная оценка (36) оказалась выше самооценки модели (0), поэтому
система использовала взвешенную; решение `reject` корректно для клипа без
видимого игрового события. Это именно то поведение, которое требуется:
не превращать отсутствие события в «кандидата» только из-за популярности.
