# План доводки AI Clip Studio до MVP

Основание: `docs/AUDIT.md`, ветка `mvp-hardening`, baseline `baseline-v0.2`.
Принцип: сначала фундамент и надёжность, затем качество анализа, затем монтаж;
каждый этап заканчивается тестами и отчётом.

## Этап 2. Фундамент

Цель: запускаемое окружение, достоверное состояние, официальный/временный
Twitch-провайдер, надёжное скачивание.

- `config.py`: полная конфигурация из `.env`, проверка значений и путей,
  `ConfigError` с понятными сообщениями, безопасные значения по умолчанию.
- `logging_setup.py`: консоль + ротация файла, `clip_id` в каждой строке,
  тайминги этапов, без секретов.
- `models.py`: добавить `game_id`, `StageResult`, `Moment`, `DownloadResult`,
  `RenderResult`; сохранить обратную совместимость.
- `utils.py`: безопасные имена, ffprobe-информация, free space, fingerprint
  файла, атомарная запись, парсинг времени.
- `database.py`: schema v3, миграции с бэкапом, индексы, история статусов,
  захват задачи (claim), восстановление зависших статусов, `READY` только
  после проверки файла, отчёты по очереди.
- `src/twitch/*`: сохранить GraphQL по умолчанию; усилить обработку ошибок,
  пагинацию, health-check схемы, явные ошибки «игра не найдена»/«схема
  изменилась»/«нет клипов»; Helix — полноценный опциональный провайдер,
  покрытый mock-тестами.
- `downloader.py`: путь `raw_clips/<clip_id>_source.mp4`, проверка
  существующего файла и `local_path`, retries, очистка `.part`, проверка
  FFmpeg, свободного места, целостности.
- `requirements.txt`, `.env.example`, `start.bat`, `launcher.py`: установка
  с нуля, проверки Python/venv/FFmpeg/yt-dlp/Ollama/моделей/Twitch, понятные
  ошибки, `pause` при сбое.
- Удалить/переместить устаревшие скрипты, переписать README в UTF-8.

Критерии приёмки:
- `python -m venv` + `pip install -r requirements.txt` без ошибок;
- `python -m src.main health` проверяет всё и не врёт;
- миграция существующей `data/clips.db` сохраняет данные и делает бэкап;
- тесты на config/db/twitch/downloader/utils проходят.

## Этап 3. Надёжность конвейера

Цель: очередь, которую можно прервать и продолжить, и точная передача файлов.

- `pipeline.py`: стадии с структурированным результатом, кэш этапов,
  claim/lock, `max_parallel`, восстановление после сбоя, изоляция ошибок,
  отдельные статусы `REVIEW`/`ANALYSIS_ERROR`.
- `moment.py`: выбор границ вокруг пика, защита слов/реакции/развязки,
  min/max длительность, расширение короткого фрагмента.
- `editor.py`: точный источник и границы, режимы `blur`/`crop`, атомарный
  вывод, проверка 1080x1920/длительности/аудио.
- `subtitler.py`: ASS с PlayRes 1080x1920, переносы, лимиты, два режима,
  корректные тайминги; SRT — для просмотра.
- `main.py`: `run`, `resume`, `retry --clip/--all-failed`, `status`,
  `review`, `cleanup`, `health`.
- Логирование каждого этапа: clip_id, этап, время, результат, ошибка.

Критерии приёмки:
- прерывание и повторный запуск продолжают очередь, не перекачивая и не
  переанализируя готовое;
- ошибка одного клипа не мешает остальным;
- `READY` невозможен без проверенного файла;
- тест «два клипа подряд + сбой на одном» проходит.

## Этап 4. Интеллектуальный анализ

Цель: оценивать содержание, а не просмотры.

- `audio_analyzer.py`: кэш транскрипции, слова/сегменты, громкость, паузы,
  смех/крик/реакция с отличием от шума, сохранение в `transcript.json`.
- `vision_analyzer.py`: равномерная сетка кадров + сцен-чейнджи, dHash через
  FFmpeg (без OpenCV), корректные метки времени, батчинг, кэш
  `vision.json`, последовательное описание.
- `auto_curator.py`: единый промпт (игра, транскрипт, события, таймлайн,
  длительность), строгий JSON, один корректирующий retry, confidence-гейт,
  отдельные ошибки анализа.
- `scoring.py`: веса 20/15/20/15/10/10/10, проверка NaN/inf, категории,
  `candidate`/`reject`/`review`, обоснование.
- Выбор моделей: сравнительный тест `moondream`/`llava` на 3 реальных клипах
  (качество описания, RU/EN, скорость, VRAM), настройка через `.env`.
- Двухступенчатость: быстрый прескрин/vision-модель + финальное решение
  текстовой моделью; тяжёлые модели не держать в VRAM одновременно.

Критерии приёмки:
- 3 реальных клипа проходят анализ без падений;
- таймкоды кадров соответствуют видео;
- повторный анализ использует кэш;
- есть отчёт сравнения моделей;
- куратор возвращает валидный JSON с конкретным обоснованием.

## Этап 5. Монтаж

Цель: готовый вертикальный ролик вокруг выбранного момента.

- 1080x1920, 9:16, blur-фон по умолчанию, crop-режим опционально;
- игровое видео не обрезает HUD (fit по ширине), фон размыт;
- исходный звук сохранён и синхронизирован;
- ASS-субтитры читаемы, в пределах кадра, RU/EN, normal/accent;
- качество/CRF/пресет настраиваются;
- проверка результата FFprobe до `READY`; исходник не удаляется;
- экспорт `exports/<Категория>/<clip_id>_<slug>.mp4`.

Критерии приёмки:
- визуальная проверка кадра с субтитрами;
- 1080x1920, длительность в допуске, аудио на месте;
- субтитры не выходят за кадр, синхронизированы с речью.

## Этап 6. Проверка

- Интеграционный тест на синтетическом видео: discovery → download (mock) →
  audio/vision (mock) → curator → moment → render → READY.
- Повторный запуск, несколько клипов, сбой API, сбой модели, сбой рендера,
  битый JSON, отсутствующий файл.
- Проверка Windows-путей (пробелы, кириллица, `F:\...`).
- `pytest -q` и `pytest -m integration`.
- README, `.env.example`, инструкция по моделям, ограничения GraphQL.
- Финальный отчёт по 15 критериям MVP.

## Вне рамок MVP

Этапы A–E из ТЗ (мониторинг стримеров, длинные VOD, Telegram-бот, автономная
работа, публикация) не реализуются, пока конвейер не стабилен. Внешний API
куратора — только как опциональный режим, если останется время; локальный
сценарий обязателен.

## Риски

- Twitch GraphQL может измениться или ограничить публичный Client-ID.
  Смягчение: провайдер, health-check, понятливые ошибки, Helix на будущее.
- Качество локальных моделей на 8 GB VRAM ограничено. Смягчение: сравнение
  моделей, кэш, батчинг, возможность сменить модель.
- Whisper на CPU медленный. Смягчение: кэш, `small`/`base`, VAD.
- Windows-пути в FFmpeg-фильтрах. Смягчение: работа через `cwd`, ASS вместо
  SRT-тегов, тесты с пробелами и кириллицей.
- Авторские права на клипы. В MVP не публикуем автоматически; это остаётся
  ответственностью пользователя.
